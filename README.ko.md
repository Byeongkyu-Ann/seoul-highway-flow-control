# NoJam — 서울 도시고속도로망 거시적 교통류 제어

[English](README.md) | **한국어**

서울 8대 도시고속도로의 교통류 붕괴를 사전에 예측하고, 정체가 생기기 전에 네트워크 전체 단위로
차량을 분산시키는 설계아이디어 부문 공모전 프로젝트입니다.

## 개요

일반적인 내비게이션과 공공 ITS는 정체가 이미 발생한 뒤에 이를 감지하고 개별 운전자에게
우회로를 안내합니다. 많은 운전자가 같은 우회로로 몰리면 그 우회로가 새로운 병목이 됩니다. 정체가
해소되는 것이 아니라 위치만 이동하는 것입니다.

이 프로젝트는 **거시적 흐름 제어**를 제안합니다. 모든 고속도로 구간의 가까운 미래 상태를 예측하고,
이를 시간에 따라 변하는 통행 비용으로 변환한 뒤, 정체가 형성되기 전에 차량을 여러 경로로 분산시킵니다.

```
과거 교통량 + 기상 + 사고율 + 공휴일 데이터
            |
            v
  LSTM + Transformer 앙상블  ->  VOL / SPD / OCC 3스텝(15분) 예측
            |
            v
  BPR 비용 함수  ->  예측값으로부터 구간별 통행 비용 산출
            |
            v
  Yen's K-최단경로 + Softmax 다차량 배정 + 혼잡 피드백
            |
            v
  5분마다 재실행하는 Dijkstra  ->  PyQt5 GUI에 경로 표시
```

테스트 네트워크는 강변북로, 내부순환로, 동부간선도로, 북부간선도로가 고리형으로 얽힌 강북 지역의
9개 노드, 20개 엣지 부분망입니다. Yen's 알고리즘이 물리적으로 분리된 대안 경로를 찾으려면 이런
고리형/격자형 토폴로지가 필요하기 때문에 이 지역을 선택했습니다.

## 데이터

서울 도시고속도로망 160개 구간의 5분 단위 교통 감지 데이터입니다. 2025년에 수집되었으며, 구간별
160개 CSV를 병합해 **16,491,792개 레코드, 25개 변수**로 구성된 데이터셋을 만들었습니다. 16개
노선(`ROUTE_ID`)과 160개 구간(`LINK_ID`)을 포괄합니다.

| 필드 | 의미 | 전처리 |
|---|---|---|
| `ROUTE_ID` (16종) | 노선 식별자 | 레이블 인코딩 -> 8차원 임베딩 |
| `LINK_ID` (160종) | 구간 식별자 | 레이블 인코딩 -> 50차원 임베딩 |
| `VOL` | 5분당 교통량 | log1p + 표준화. 타겟이자 자기회귀 입력 |
| `SPD` | 속도(km/h) | 표준화. 타겟이자 자기회귀 입력 |
| `OCC` | 점유율(%) | log1p + 표준화. 타겟이자 자기회귀 입력 |
| `day_sin/cos`, `hour_sin/cos` | 날짜·시간 주기성 | 삼각함수 인코딩, 원시값 사용 |
| `Past SPD` | 이전 구간 속도 | 표준화 |
| `acc_weekday/month/hour` | 요일·월·시간대별 사고율 | Min-Max 스케일링 |
| 강수량(mm), 적설(cm) | 기상 | log1p + Min-Max |
| 시정(10m) | 기상 | log(1+x) |
| `is_holiday` | 공휴일 여부 | 0/1 |
| 요일 (`wd_0`~`wd_6`) | 요일 | 원핫인코딩(7차원) |

160개 구간 각각에 **`SEQ_LEN=12`**(과거 1시간)의 슬라이딩 윈도우를 독립적으로 적용해
**`PRED_STEPS=3`**(미래 15분)을 예측하며, 총 **16,489,552개** 학습 샘플을 만들었습니다. 미래
정보가 과거로 유출되는 것을 막기 위해 시간 순서를 유지한 채 훈련 70% / 검증 15% / 테스트 15%로
분할했습니다.

## 예측 모델

독립적으로 학습한 두 기저 모델의 출력을 스태킹 앙상블로 결합합니다.

| | LSTM | Transformer |
|---|---|---|
| 역할 | 단기 연속성, 게이트 기반 기억 | Self-Attention을 통한 장거리·주기적 패턴 |
| 파라미터 수 | 5,460,553 | 292,553 |
| 구조(베이지안 최적화 이후) | 1층, 은닉 512 | 인코더 2층, `d_model=256`, 헤드 4개, Pre-LN |
| 손실 함수 | Peak-Weighted MSE: `L = mean[(1 + α·|y_true|)·(y_pred − y_true)²]`, α=0.5 | 동일 |
| 옵티마이저/스케줄 | AdamW, Linear Warmup + CosineAnnealingLR, Gradient Clipping | 동일 |
| 하이퍼파라미터 탐색 | Optuna TPE, 30 trial, 최적 Val Loss 0.0490 | Optuna TPE + Hyperband, 30 trial, 최적 Val Loss 0.0389 |

**테스트셋 결과(단독 모델):**

| 타겟 | LSTM RMSE | LSTM R² | Transformer RMSE | Transformer R² |
|---|---|---|---|---|
| VOL(교통량) | 25.07 | 0.9364 | 23.37 | 0.9447 |
| SPD(속도, km/h) | 5.99 | 0.8775 | 5.53 | 0.8939 |
| OCC(점유율) | 3.64 | 0.8779 | 3.25 | 0.9002 |
| **평균** | – | 0.8973 | – | 0.9129 |

두 기저 모델 출력을 18차원으로 이어붙인 뒤 베이지안 최적화 가중 평균, XGBoost, Random Forest,
Ridge 회귀 네 가지 스태킹 방법을 검증 세트로 비교했습니다. **한 방법이 모든 타겟에서 1등은
아니었기 때문에**, 최종 시스템은 타겟별로 다른 앙상블을 사용합니다.

| 타겟 | 최우수 방법 | R² | 최우수 단독 모델 대비 |
|---|---|---|---|
| VOL | BO 가중 평균 (Transformer 가중치 약 0.86~0.91) | 0.9453 | +0.07%p |
| SPD | Ridge 스태킹 | 0.8972 | +0.33%p |
| OCC | Ridge 스태킹 | 0.9082 | +0.80%p |

SPD·OCC에서 Ridge가 비선형 스태킹 기법(XGBoost, Random Forest)보다 좋았던 이유로 보고서는, 두
기저 모델의 예측값이 이미 정답과 선형에 가까운 관계를 형성하고 있어 추가 비선형 변환이 오히려
과적합을 유발한다는 점을 들었습니다.

## 경로 탐색 계층

- **구간 비용**: BPR 함수 `t = t₀ · [1 + α·(V/C)^β]`, α=0.15, β=4.0. V/C는 `OCC/100`과
  `VOL/LINK_CAPACITY` 중 더 큰 값을 사용합니다. 둘 중 더 혼잡한 신호를 반영하는 보수적 선택입니다.
- **다차량 배정**: Yen's K-최단경로(K=3)로 후보 경로를 찾고, 비용에 대한 Softmax(온도 T=2.5)로
  차량 묶음을 여러 경로에 확률적으로 분산시킵니다. 단일 최단경로로 몰아넣지 않습니다. 배정된
  차량 수는 해당 구간의 VOL 예측값에 반영되어 다음 배정의 비용을 다시 높입니다.
- **재탐색**: 갱신된 그래프에서 Dijkstra를 5분마다 다시 실행합니다.
- **실시간 입력**: 요청 시점의 강수량, 적설, 시정을 기상청 사이트(`weather.go.kr`)에서 크롤링하며,
  크롤링이 실패하면 이전 값을 그대로 유지합니다.
- **인터페이스**: PyQt5 데스크톱 앱에서 출발지와 목적지를 입력하면 추천 경로를 보여줍니다.

## 결과

- 단독·앙상블 예측 정확도는 위 표를 참고하세요. 테스트셋에서 VOL/SPD/OCC 전체에 걸쳐 R² 0.90~0.95
  범위입니다.
- 제안서 요약에 보고된 시스템 단위 경로 탐색 결과는, 모든 차량을 같은 최단경로로 보내는 기존
  방식 대비 **전체 도로망 비용 8.5% 절감**입니다. Softmax 기반 다차량 분산이 대안 경로를 새로운
  병목으로 만들지 않도록 억제한 효과로 설명됩니다.
- 이 결과는 강북 지역 9개 노드 테스트 네트워크에서 얻은 것입니다. 서울 8대 고속도로 전체망에서는
  실행하지 않았습니다.
